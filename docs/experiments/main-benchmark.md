## Generation Command

The manifests were generated from the fixed-budget planner with these settings:

```bash
python3 - <<'PY'
from pathlib import Path

from go_explore.fixed_budget import FixedBudgetPlanConfig, plan_fixed_budget_runs, write_fixed_budget_manifest
from go_explore.harbor import HarborRunConfig

manifest = plan_fixed_budget_runs(
    FixedBudgetPlanConfig(
        experiment_id="phase4-smoke-regex-log-001",
        base_config=HarborRunConfig(
            jobs_dir=Path("jobs"),
            agent=None,
            agent_import_path="go_explore.agents.factory:SnapshotAwareTerminus2",
            env="daytona",
            dataset="terminal-bench@2.0",
            model="anthropic/claude-haiku-4-5-20251001",
            task_name="regex-log",
            n_tasks=1,
            n_attempts=1,
            n_concurrent=1,
            export_traces=True,
        ),
        job_prefix="phase4-smoke-regex-log",
        total_token_budget=100000,
        methods=("single", "retry", "random_branch", "promising_branch"),
        seeds=(0,),
        n_retries=5,
        n_branch_continuations=2,
        branch_root_fraction=0.3,
        snapshots=(),
    )
)
write_fixed_budget_manifest(
    manifest,
    Path("docs/experiments/main-benchmark/manifests/smoke/regex-log.json"),
)
PY
```

The committed files were generated by applying the same settings across the
smoke and primary task lists.

## Launch Commands

Before launching:

```bash
set -a; source .env; set +a
export PATH="$HOME/.local/bin:$PATH"
export PYTHONPATH="$PWD"
```

Run a ready job by copying its `command` array from the manifest and executing
it. For example, the smoke `regex-log` single-run command is:

```bash
harbor run \
  --agent-import-path go_explore.agents.factory:SnapshotAwareTerminus2 \
  --env daytona \
  --jobs-dir jobs \
  --n-attempts 1 \
  --n-concurrent 1 \
  --dataset terminal-bench@2.0 \
  --model anthropic/claude-haiku-4-5-20251001 \
  --include-task-name regex-log \
  --n-tasks 1 \
  --job-name phase4-smoke-regex-log-single-seed-0 \
  --export-traces
```

Branch methods must run in two stages:

1. Run the `random_branch` and `promising_branch` root jobs from the manifest.
2. Use each completed root archive to launch continuations:

```bash
uv run python -m go_explore.cli continue-from-snapshots \
  jobs/phase4-smoke-regex-log-promising-branch-seed-0-root \
  --from-archive \
  --selector-mode archive_priority \
  --max-snapshots 2 \
  --job-prefix phase4-smoke-regex-log-promising-branch-seed-0 \
  --execute
```

For the random branch condition, use:

```bash
uv run python -m go_explore.cli continue-from-snapshots \
  jobs/phase4-smoke-regex-log-random-branch-seed-0-root \
  --from-archive \
  --selector-mode random \
  --selector-seed 0 \
  --max-snapshots 2 \
  --job-prefix phase4-smoke-regex-log-random-branch-seed-0 \
  --execute
```

## Analysis Commands

After a task's jobs finish, summarize each Harbor job:

```bash
uv run python -m go_explore.cli summarize-job jobs/<job-name>
```

Build analysis tables for a single task by passing the manifest and observed job
directories:

```bash
uv run python -m go_explore.cli build-analysis-tables \
  --manifest docs/experiments/main-benchmark/manifests/smoke/regex-log.json \
  --job-dir jobs/phase4-smoke-regex-log-single-seed-0 \
  --job-dir jobs/phase4-smoke-regex-log-retry-seed-0-attempt-0 \
  --job-dir jobs/phase4-smoke-regex-log-random-branch-seed-0-root \
  --job-dir jobs/phase4-smoke-regex-log-promising-branch-seed-0-root \
  --continuation-report jobs/phase4-smoke-regex-log-promising-branch-seed-0-root/continuation-report.json \
  --event-log jobs/phase4-smoke-regex-log-promising-branch-seed-0-root/events.jsonl \
  --output-dir docs/experiments/main-benchmark/analysis/smoke/regex-log
```

## Current Execution Status

No new live jobs were launched for this branch. The execution ledger records:

- `not_started` for ready root, single, and retry jobs,
- `blocked_pending_root_archive` for branch continuations whose root archives
  do not exist yet.

This preserves the missing run state explicitly for review. It also avoids
mixing a partial expensive benchmark into a PR whose durable artifact is the
frozen execution plan.

## Blockers Before Full Launch

The full benchmark can run with the current components, but it requires manual
or scripted orchestration around the two-stage branch methods:

1. Launch all ready `single`, `retry`, and branch-root jobs.
2. Wait for branch roots to finish and write `archive.json`.
3. Launch continuations from each root archive with the selector mode matching
   the method.
4. Build analysis tables from the manifest, observed job dirs, continuation
   reports, event logs, and any repeated-work reports.
5. Update `execution-status.csv` from `not_started` to completed or failed
   artifact paths.

A future automation ticket should turn those steps into a resumable executor so
P4-T002 can be run without hand-copying commands.
